# ADR-0001: 앱 성격 전환 — 대화형 에이전트 → 문제풀이 앱

| 항목 | 내용 |
|------|------|
| 날짜 | 2026-08-31 (확정) · 문서화 2026-09-02 |
| 상태 | Accepted |
| 컨텍스트 | 초기 기획은 "AI와 자유대화하는 에이전트". 그러나 실어증 재활 관점에서 구조화된 문제풀이(마이크로 답안 제출)가 치료적 가치와 채점·시각화 목적에 부합. |
| 결정 | 앱을 문제풀이 앱으로 재정의. 세션 = 평가지표 8턴(무작위) + 이야기 4~8턴. TURN = "AI 제시 1회 + 사용자 반응 1세트" 통합형. AI TTS 진행은 유지. |
| 결과 | 세션/턴/녹음 DB 전면 재설계, WebSocket 중심 설계 축소, 계획서 v1.8 전환. |

# ADR-0005: 음성 파일 3단계 저장 전략

| 항목 | 내용 |
|------|------|
| 날짜 | 2026-09-02 |

# ADR-0006: 문제 일괄 생성 + TURN INSERT 전략 (로컬 turnId 리매핑)

| 항목 | 내용 |
|------|------|
| 날짜 | 2026-09-02 |
| 컨텍스트 | 컨테이너는 DB TURN PK를 모른 채 문제·TTS 파일명 생성. 선 INSERT 방식은 응답 후 UPDATE 2배 발생. |
| 결정 | 턴 선 INSERT 하지 않음. 컨테이너가 로컬 번호(1~8)로 problemList 반환 → 백엔드가 응답 수신 시점에 시퀀스로 실제 PK 발급, INSERT 1회로 완료. TTS 파일도 실제 TURN PK로 리네임 후 OCI 적재. |
| 결과 | DB 접근 최소화, 고아 턴 방지, 이어하기 판별 단순화(INSERT 완료=문제 생성 완료). |

# ADR-0007: TURN.status 상태머신 (PENDING / SUBMITTED / SCORED)

| 항목 | 내용 |
|------|------|
| 날짜 | 2026-09-02 |
| 컨텍스트 | 문제 선생성 + 순차 풀이 + 이어하기 요구로 턴 단위 상태 추적 필요. |
| 결정 | TURN.status 신설: PENDING(출제·미풀이) → SUBMITTED(답안 제출) → SCORED(채점 완료). 세션 이어하기는 status 기반 판별. |
| 결과 | 미완료 세션 재입장 시 이어하기/폐기·신규생성 옵션 제공 가능. |

# ADR-0008: REPORT 테이블 폐지 → LEARNING_SESSION 통합

| 항목 | 내용 |
|------|------|
| 날짜 | 2026-09-02 |
| 컨텍스트 | 리포트 = 세션 단위 1:1 데이터. 지표별 점수는 TURN 집계로 산출 가능해 별도 테이블이 중복. |
| 결정 | REPORT 테이블 신설 안 함. LEARNING_SESSION에 `AQ`(NUMBER(3), 0~100, 정수·올림은 컨테이너 책임) + 피드백 6컬럼(LISTEN/NAMING/SHADOWING/SELF_TALK/TALK/TOTAL_FEEDBACK, CLOB nullable) 통합. |
| 결과 | 리포트 생성 = 세션 종료 시점 컨테이너 요청 1회 → 세션 UPDATE. |

# ADR-0009: 실력 산정식 — 최근 20세션 중 상위 10 평균

| 항목 | 내용 |
|------|------|
| 날짜 | 2026-09-02 |
| 컨텍스트 | 지표별 실력(대시보드)과 유저 대표 AQ(userAQ)의 산정 방식 필요. |
| 결정 | 공통 산정식: **최근 20개 세션 중 (지표별/AQ) 상위 10개 세션의 평균.** userRT도 유사 방식(최근 naming 20개 중 발화시간/음절수 최단 10개, 0개면 null). |
| 결과 | 대시보드·userAQ·naming RT가 동일 패턴 — 쿼리 재사용. 세션 0개는 null(추후 가입 설문 임시 AQ 주입 예정). |

# ADR-0010: 발화지표 rename + 정의의 계약서 이관

|------|------|
| 날짜 | 2026-09-02 |
